Stock Jolt0.8.23 binary7bf7acae..., Chez10.4.1 wrapper. No compiler/data.json

## Mechanism

The current nested-text path first encodes inner JSON to private ASCII bytes,
then the outer encoder scans them to emit a JSON STRING. The new specialization
uses the SAME encoder definition with a stringified byte sink, producing the
complete escaped STRING eagerly at the original nested-call boundary. The
outer encoder copies only those privately generated bytes. This is NOT raw JSON
splicing: null becomes the STRING "null", nested quotes/backslashes/slashes
are escaped again, and callers cannot supply the private literal's backing.

Inner logical bytes retain the old64MiB bound and depth128. Physical escaped
output is at most twice those ASCII bytes plus two delimiters, checked as a
fixnum. Clean-string cursor runs charge their original logical bytes when
published; escape writes charge one logical byte before expanding. Outer
copies enforce the outer call's independent byte limit without repeating the
escape scan. No input callback/late record is replayed on failure.

Uncached fusion alone loses the existing nested fragment optimization. The
new separate scope composes fusion with the same weak-root/bounded scalar-map
strategy: at most64 insertions,128KiB escaped payload bytes,4KiB/fragment.
Each cache entry additionally stores the original logical byte count so a hit
cannot bypass a smaller inner limit. Complete fragments only; chunk-crossing
maps decline caching. This metadata/weak-table overhead is NOT part of that
payload-byte cap or a hard RSS promise. New escaped entries never share a table
with old raw entries. Closure marks the writer inactive and drops table/scratch;
already returned literals own independent bytes. Old APIs keep their results.

uncached191.82ms, fused177.10ms; no gain over the current cache. Retained rather

About6% lower observed median and1% more estimated allocation against the
current cached arm. Not a causal or population-tail qualification; samplep99
is max16 and GC samples remain. All arms use the same CANDIDATE encoder,
so shared-path overhead vs the original encoder remains unisolated. SDK
policy/cache, schema learning, typed projection and nested/outer encoding are
included; live SDK queue, native/Durable I/O, Oscope, application AOT, S3 and
Rust-relative conclusions are excluded. Full bytes equality and changed-event
controls pass. This does not meet the25k/20k confirmed throughput target.

The screen's fused-cached projector duplicates the SAME28-field expression
used by other arms, inside the new scope; it uses private consumer seams, not
a production SDK/exporter API. No concurrency/delivery behavior changes.
