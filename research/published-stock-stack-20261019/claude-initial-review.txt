**Alias composition.** `:stock-span-codec` pulls `io.github.chucklehead-dev/jolt-codec` via `:deps/root "incubator/codec"` pinned to SHA `05fa8b8` (deps.edn:23-28) — the current branch's own parent commit, fetched fresh through gitlibs rather than the worktree. `:stock-span-codec-test` (deps.edn:29-31) adds only `incubator/codec/test` as an extra path plus a `-m` entrypoint — no `src` path is added, so it cannot shadow the published checkout. This correctly mirrors the documented "do not combine with `:experimental-span-codec`" warning in incubator/codec/README.md:73-77.

**Provenance oracle.** `chdb_stock_published_codec_test.clj` asserts `io/resource` for four specific files resolves into a gitlibs path containing the literal SHA `05fa8b86f38b...` (lines 16-20) — a real resource-path check, not a declaration-only assumption. This is a good, concrete anti-shadowing guard. One gap: `chdb_dependency_test.clj` has an established pattern of positive-pin-accepted *and* negative-prior-pin-rejected assertions for crypto/otel/chdb/data.json (e.g. lines 187-200), but the new `jolt-codec` pin has no equivalent entry there — its only coverage is the single positive path-contains check above, with no negative control proving an older SHA or wrong repo would be rejected. That asymmetry is worth closing before calling this pin as rigorously qualified as the others.

**CI failure propagation.** `experimental-codec-stock.yml` is reasonably tight: `set -euo pipefail`, checksummed tarball and binary, an explicit `jolt --version` string check, `(= 14 (:test r))` assertion before `System/exit`, and a final `-Srepro -M:stock-span-codec:stock-span-codec-test` run from repo root inside a `(cd ../.. && ...)` subshell that doesn't perturb later steps. The 8-minute timeout is plausible given the job only downloads one release artifact and runs a handful of in-memory tests — it's not implausibly tight, but I haven't observed an actual hosted run's wall-clock time.

**Documentation boundaries.** README.md:139-165 and incubator/codec/README.md both repeatedly scope claims correctly — "not a fully upstream-only dependency stack," "no throughput claim," "does not qualify complete exporter/application standalone builds." The chdb.clj docstring (1896-1903) and CHANGELOG entries are consistent with this, including noting the `:experimental-span-codec?` flag accepts either the published or checkout-local alias. No doc overclaims what the code/tests actually cover.

**Local vs. unobserved hosted CI.** Everything above is static review only — I did not execute anything. The candidate's claims (published-module gate passed, canonical `-M:test` exit 0, native/direct-layout counts, raw-ticks Durable pass) are asserted by the user, not independently verified by me, and the hosted GitHub Actions run of `experimental-codec-stock.yml` is likewise unobserved. The self-referential `:deps/root` pin to this same repo's own prior commit means the workflow's success is contingent on `05fa8b8` already being resolvable from the public remote — true if that commit is already on `main` (consistent with the git log shown), but worth confirming before treating a green CI run as conclusive.

**Net assessment:** the alias separation and resource-path oracle are sound; the main weakness is the missing negative-control pin test for the new codec dependency, and all pass/fail claims beyond static code reading remain unverified by me.
