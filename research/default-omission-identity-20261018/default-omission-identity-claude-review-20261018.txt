## Review findings: default omission identity change (2172061 vs 96f3e47)

**Scope covered:** `json.clj` write-object (lines 903–940), `default-value-fn`/`default-write-options` (113, 1062–1080), native fast path `jolt_native.ss` (djn-checked-flags 155–184, djn-write! map branch 320–341), `jolt_byte_writer.ss` (stock-slots capture 44–46, omit check 209–211), both test files, README/CHANGELOG.

**Mechanism:** The omission contract ("if value-fn returns itself, the property is omitted") is checked three times — portable (`json.clj:927-929`), native-string (`jolt_native.ss:334`), native-byte (`jolt_byte_writer.ss:209`). All three now branch: when `value-fn` is `identical?`/`eq?` to the private `default-value-fn`, the omission test uses identity against the raw value; otherwise (custom `value-fn`) it still uses `=`/structural equality against the transform's output. The native admission gate (`djn-checked-flags`, `jolt_native.ss:155-170`) independently forces *any* non-default `:value-fn` (or `:key-fn`, `:indent`, etc.) to decline the fast path entirely via `eq?` against defaults, so the native writers never reach the identity-check line with a custom callback — confirmed consistent with the comment at `jolt_native.ss:328-333`.

**No correctness defects found.** The three omission-check sites are consistent with each other and with the documented contract. The identity check is only reachable when `value-fn` is provably the stock function (enforced structurally, not just by convention, in the native gate; enforced by explicit `identical?` branch in the portable path).

**Contract assessment (default vs. custom equality):**
- *Default path*: narrowed from `=` to `identical?`/`eq?`. This is the only semantic change, and it is correctly scoped — it only fires when `value-fn` is the literal default function object, which is private and not constructible by callers except via the publicly exposed `(:value-fn json/default-write-options)` marker itself (`json.clj:1062-1080`). A map value that merely claims structural equality to that function (e.g., a custom-equals record) would have been incorrectly omitted under the old `=` semantics and is no longer omitted under `identical?`. This is the intended, disclosed narrowing — not a regression, since matching a function object via custom `.equals` was already an obscure/unintended trigger of omission.
- *Custom path*: unchanged, still `=`, preserving transformation order, callable-object custom equality, and portable-only fallback for callers needing richer semantics. Correctly untouched at all three sites.
- *Reader* (`read-object`, `json.clj:580-603`): untouched, still unconditional `=` at line 591 regardless of whether `value-fn` is default — matches the claim "reader value functions are untouched." This is an asymmetry (write default path is fast/identity, read default path still calls through `=` every time), but it's explicitly out of scope per the evidence packet, and not a correctness issue.

**Regression-control non-vacuousness:** `json_default_omission_test.clj` is well-constructed, not vacuous. It patches the native `jolt=2` primitive in-process (necessary because `=` is intrinsified and a `with-redefs` of the public Var wouldn't observe it), and includes a positive control (`marker-checks`, lines 21-28: asserts the probe fires exactly once on a direct call) before asserting zero calls during the default-path write — so an inert/broken probe would fail the control rather than silently passing. The custom-value-fn test asserts calls `>= 4`, confirming `=` is still invoked for custom callbacks. A separate test re-evaluates `jolt_byte_writer.ss` source with a locally shadowed `jolt=2` to probe the byte-writer path specifically. `literal-default-marker-still-omits-and-all-writers-agree` cross-checks portable output against all three native writer variants on the literal marker, including as a sorted-map value (the originally expensive case). `json_test.clj:747-756` duplicates the behavioral (non-instrumented) assertions at the Clojure-API level for both array-map and sorted-map containers.

**Minor observation (not a defect):** The native omission checks (`jolt_native.ss:334`, `jolt_byte_writer.ss:209`) use `eq?` unconditionally without re-verifying `value-fn` is the default inline — they rely entirely on the upstream admission gate having already excluded custom callbacks. This is correct as implemented, but it is a non-local invariant (correctness of the omission line depends on an admission check dozens of lines away in a different function); a future edit to the gate that forgets to re-exclude custom `:value-fn` would silently make custom callback values compare by identity instead of `=`. Worth a defensive comment/assertion if this file is touched again, but no action needed now.

**Verdict:** The identity-only narrowing for the default marker is justified, consistently implemented across all three write paths, accurately disclosed in README/CHANGELOG, and backed by non-vacuous regression tests (including an isolated-process equality-call observer with a positive control). No custom-callable equality bypass found.
