## Review: published-scoped codec canonical integration (deps/published-scoped-codec-20261020)

**Scope covered:** the full evidence diff (CI workflow, `deps.edn`, `chdb.clj`, `attribute_projection.clj`, `native_attributes.clj`, `native_projection.clj`); first canonical wiring of `incubator/codec/src/jolt/{codec,traversal}/experimental.clj` (read in full); the new `chdb_published_scope_capability_test.clj` and `chdb_stock_published_codec_test.clj`; docs/README/CHANGELOG/research README for consistency with the diff.

### Verdict: Approve, no blockers found

**Ordering / ACK / callback semantics — sound.** `execute-closed-compact-rows!` is split into `prepare-closed-compact-rows` (builds `sql`, returns an opaque sealed `PreparedCompactInsert`) and `publish-prepared-compact-insert!` (re-checks the plan, then calls the unchanged `execute-durable-sql!`). Both run back-to-back synchronously — no lookahead, no deferred execution, no new concurrency. The original double-check pattern (validate → build SQL → re-validate → execute) is preserved exactly, just factored into two functions. The seal (`prepared-compact-seal` identity check) prevents a stray value from being published out of band, and `print-method`/`print-dup` are overridden so a prepared value can't leak SQL/telemetry text if printed.

**Opt-in isolation — sound.** `:experimental-span-codec?` and its three cache flags fail closed (boolean + implication checks) and require `durable? owned-statement-output? #{:spans} :native-guarded-byte-batch :json-compact-each-row` before the codec is even loaded. `load-experimental-span-codec!` resolves everything before any database/DDL work and throws a typed `ex-info` on any gap rather than silently downgrading. `*experimental-attribute-transform*` and `*experimental-nested-writer*` both default to `nil`, so every call site that gained an optional arg (`attrs`, `event-columns`, `link-columns`, `span-row`) falls back to the pre-existing behavior when the codec is disabled — I traced each one to confirm this.

**Nested-writer scope fencing — sound.** `*experimental-nested-writer*` is bound to `[scope-owner write]` only inside the `with-writer` wrapper around a single `(:encode codec ...)` call. The returned `:nested` fn checks `(identical? scope-owner owner)` and throws `::missing-nested-scope` otherwise, so a leaked/reused writer outside its one synchronous payload fails loudly instead of corrupting output.

**Memory/byte budget — consistent.** `encode-prefixed-records` enforces `0 <= max-bytes <= 67108864` (64 MiB), matching `max-configured-insert-bytes`, and `*insert-byte-limit*` is threaded through the codec path the same way as the non-codec path.

**Stock dependency selection — correctly isolated.** `chdb_stock_published_codec_test.clj` asserts `(io/resource ...)` resolves under the exact published Git coordinate and explicitly rejects a different SHA, owner/repo, subpath, or suffixed path — directly guarding against the checkout-local `:experimental-span-codec` alias shadowing the published one (which the docs correctly warn against combining). CI runs the published-pin gate under `-Srepro` with an explicit `:deps` map, separate from the checkout-local adapter gate. SHA provenance checks out: the research README documents `05fa8b8` (pre-nested-fragments) → `0af1008...` (current), matching the CI's absent/present cases and the capability test's expectations.

**`pmap-fold-seq-order` free-variable check — verified, not a bug.** The newly added arity check in `native_attributes.clj`'s shared Scheme source references a free `pmap-fold-seq-order` identifier unconditionally. This initially looked like it could break the *default* (non-experimental) `small-attribute-transform` path, which evaluates that source without the new `folder`-wrapping lambda. Checked against `research/library-nested-text-20261019/` evidence: `pmap-fold-seq-order` is only unbound on **stock official Jolt**; the exporter's default path runs on the **jolt-chdb native runtime**, where this identifier is already a pre-existing global (the `.ss` resources reference it unconditionally, unchanged by this diff). The check resolves fine in both the default and folder-injected contexts — no regression.

### Minor, non-blocking note
`chdb_published_scope_capability_test.clj`'s "present" branch calls `(#'exporter/load-experimental-span-codec! true true true)` directly rather than going through `exporter/exporter` as the "absent" branch does. The zero-storage-open assertion is therefore only a meaningful guarantee for the rejection path; the happy path with the current pin never exercises the full constructor's pre-storage ordering. This is acceptable given the stated goal was specifically "old capability rejection" — just flagging it so a future slice routes the positive-path check through the public constructor too if that guarantee is ever claimed.
