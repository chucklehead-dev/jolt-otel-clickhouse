## Review: payload-scoped nested JSON fragments & scratch reuse

### Blockers
None found. The owner-token/dynamic-binding scoping, the "close before WAL precompute" ordering, and the default-off flag wiring all behave as claimed by the README/commit, and each is backed by a test that would fail if the property broke.

Specifics checked:

- **Owner-token scope is per-codec (per exporter), not per-call, and this is correct.** `scope-owner` (`src/otel/exporter/chdb.clj:1300`) is created once inside `load-experimental-span-codec!`, which runs once per exporter instance. Each `:encode` invocation still gets a fresh `with-writer` scope (fresh `fragments`/`scratch` via `ffc-json-nested-scope`, `json.ss:317-332`) and a fresh dynamic `binding` of `*experimental-nested-writer*` (`chdb.clj:1314-1326`), so overlapping/nested calls on different codecs are correctly distinguished, and calls on the same codec don't share scope state. `chdb_nested_fragments_test.clj`'s `scoped-exporter-matches-default-bytes-and-restores-owner` exercises cross-codec reentry (one codec's `:nested` invoked while another codec's scope is bound) and confirms rejection, plus confirms the dynamic var unwinds to `nil` after the call.
- **Scope closes before WAL precompute.** In `prepare-closed-compact-rows` (`chdb.clj:1378-1396`), `(:encode codec)` returns the complete `bytes` only after `with-nested-text-writer`'s `finally` (`finish`) has run, clearing `table`/`insertions`/`retained`/`scratch`/`digits`. `try-snapshot` and `(:prepare-statement codec)` (the WAL precompute) run strictly afterward, outside the writer's lifetime.
- **Scratch reuse doesn't alias across calls.** `ffc-json-nested-scope` calls `(ffc-new-fragments)` fresh per `with-nested-text-writer` invocation (`json.ss:317-318`), so the 1KiB scratch buffer is scoped to one batch encode, never shared across batches or exporters. Within a batch, every final output is copied into a newly allocated bytevector (`json.ss:280-289`) before being wrapped as a Jolt byte array, so scratch never escapes as an output alias. The "budget below 1KiB gets a freshly clamped buffer" guard (`(fx=? capacity 1024)` check, `json.ss:48`) is exercised directly by `nested_fragment_test.clj`.
- **Exception paths don't leak retained state or let a later record observe a dropped one.** `failed-projection-retires-scope-with-original-error` confirms the original exception value survives unwrapped, only the record before the throw was seen, and the writer/dynamic var are retired.
- **Flag is genuinely default-off and gated.** `experimental-span-nested-fragment-cache?` defaults `false` (`chdb.clj:1948`) and is validated to require `experimental-span-codec?`, which itself requires durable + owned-statement + spans-only + `:native-guarded-byte-batch` + `:json-compact-each-row` (`chdb.clj:1949-1967`) — it cannot silently activate under any other configuration. (Whether Oscope's actual config sets these flags is outside the reviewed file set and wasn't checked here.)

### Test / interpretation gaps (non-blocking)

1. **CI aggregate test count isn't independently reconcilable from the reviewed files.** `.github/workflows/experimental-codec-stock.yml` hardcodes `(= 23 (:test r))` for a 5-namespace bundle that includes `nested-fragment-test` (5 of those 23), then separately runs `stock-span-codec-test` (no count asserted at the workflow level) and `chdb-nested-fragments-test` (asserts `(= 3 (:test r))` internally). The README's final "28 tests / 287 assertions" figure can't be reconstructed from 23 + 3 without knowing `stock-span-codec-test`'s own count, a file outside this review's scope. Worth confirming that arithmetic separately rather than trusting the README total at face value.
2. **No integration-level test exercises same-codec reentrant/nested scope usage end-to-end through the exporter.** True nested `with-nested-text-writer` calls on one codec are tested at the low-level codec layer (`nested-scopes-and-outer-output-own-their-bytes` in `nested_fragment_test.clj`), and cross-codec reentry is tested at the exporter layer (`chdb_nested_fragments_test.clj`). There's no test for same-codec reentry specifically through `otel.exporter.chdb`'s own `:encode`/`:nested` wiring, though nothing in the wiring suggests it would behave differently from the two covered cases.
3. **Per-value nested-text budget (67108864 bytes / depth 128) is hardcoded and decoupled from the exporter's configured `insert-byte-limit`.** This is pre-existing behavior shared with the non-cached `write-nested`/`prepare-nested-text` path (unchanged by this diff), not a new gap, but it means a single span's Events/Links JSON is bounded by the fixed 64MiB cap rather than the batch's actual 8MiB/64MiB-configured limit; the overall batch limit is still enforced by the outer `encode-prefixed-records` call.
4. **Performance narrative in `research/nested-fragments-20261019/README.md` is appropriately hedged** — it explicitly disclaims population-tail, target, and S3/Rust/app-ingestion claims, and states the 25k p50/20k p99 objective is unmet. No overclaiming found in the text reviewed; the pooled-rate/allocation numbers are self-reported and weren't independently re-run as part of this read-only review.
