**Defects/limitations that need explicit scope labels (some already present, some not):**

1. **Missing `with-instrumentation-suppressed` wrapper.** `execute-durable-sql!` (chdb.clj:1567-1577) wraps `durable/execute-owned-and-flush!` in `context/with-instrumentation-suppressed`; the harness's measured `insert!` calls `execute-owned-and-flush!` directly, skipping that wrapper. If that macro does non-trivial dynamic-var binding or span suppression work, the native arm is measuring a cheaper code path than what `execute-durable-sql!`/the real exporter actually runs. This isn't labeled anywhere in the writer output and should be, or the wrapper should be included.

2. **Conflated warmup categories.** `:warmups 3` is a single aggregate number bundling one SDK-shaped capture call and two direct `execute-owned-and-flush!` calls. The validator only checks the aggregate `3`; the "1 exporter + 2 direct" breakdown is reconstructable only by reading the writer source, not independently verifiable from persisted data.

3. **Asymmetric instrumentation in the SDK arm.** The SDK arm's `with-redefs` wraps *every* one of the 35 `execute-durable-sql!` calls (incrementing `calls`, conditionally resetting `statement`) inside the delegated workload's own timed region, while the native arm's measured loop has zero such wrapper.
