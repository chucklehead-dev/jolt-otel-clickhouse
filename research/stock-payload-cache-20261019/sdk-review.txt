## Findings — payload cache folder injection (relative to `c407d5f`)

**Scope confirmed:** `otel.any-value/scalar-string-map-payload-converter[*]` gained an optional `folder` arg threaded through to `any-value-native/load-scalar-string-map-payload-cache!`, which picks a one-time-compiled `scalar-string-map-payload-cache-injector` (closes the `.ss` factory source over a `pmap-fold-seq-order` lambda parameter) instead of the stock `scalar-string-map-payload-cache-factory` delay. No `define` introduces a global binding anywhere in this path — `pmap-fold-seq-order` stays a lexical parameter, matching the tests' `global-folder?` checks.

**Old arities / default fallback — intact.** The 0-arg/2-arg public arities still resolve to `folder = nil`, which in `any_value_native.clj` routes to the original, unmodified `@scalar-string-map-payload-cache-factory` delay — byte-identical code path to before this change. No regression risk for existing non-folder callers.

**Blast radius of the folder is narrower than the docstring's general "visitor receives (key value accumulator)" language suggests.** In `payload_scalar_string_map_cache.ss`, `pmap-fold-seq-order` is invoked exactly once, inside `weight`, and only over `result` — the SDK's own already-admitted, trusted output pmap — never over the caller-supplied input `m`. `lookup` and `fresh` never call the folder at all (confirmed by the test asserting a warm hit doesn't re-invoke it). So a misbehaving folder can only corrupt **budget/admission bookkeeping** (how much of `max-chars`/`max-insertions` gets charged), never the correctness of a returned conversion — conversion output still comes solely from `original-try-scalar-string-map`/`original-try-sorted-scalar-string-map`.

**Trust contract gap: no isolation of a throwing/hanging folder at call time.** The 3-arity arity check (`procedure-arity-mask ... 3`) is enforced once, at construction (when the injector lambda is applied to the folder), and construction failures are caught by `catch Throwable` in `any_value.clj`/`any_value_native.clj` and surfaced as a clean `nil` — matches `bad-arity-and-noncallable-folders-decline-at-construction`. But a folder that passes the arity check and is still badly behaved at *runtime* (throws, infinite-loops, or mutates during `weight`'s fold) is not guarded: nothing wraps the per-entry `store!` call in a catch, so an exception from inside the folder propagates straight out of the returned converter closure into the caller's hot path, rather than declining to nil like every other control in this module. This is consistent with the docstring's explicit disclaimer ("not validation of arbitrary third-party callbacks," "must visit every entry once without mutation") — i.e., it's a documented trust boundary, not a bug — but it means the "Optional folder... avoids installing global helpers" framing should not be read as "safe against an untrusted folder." Only the construction-time shape is checked; runtime purity/termination is pure trust.

**Invalid folder construction:** non-callable (`42`) and wrong-arity folders both correctly decline to `nil` via the same `unless`-raises → `Throwable` catch → `nil` pipeline, with no global leakage (`global-folder?` stays false in both cases) — verified by the dedicated test and consistent with the code's error path.

**The 19-test gate genuinely exercises the existing 16-test cache-correctness suite against real folder injection**, not just the 3 new tests. `-main` binds `constructor`/`budget-constructor` to the *original* un-redefined vars at namespace-load time (before `with-redefs` is active), then uses `with-redefs` to make `any/scalar-string-map-payload-converter[*]` close over the injected folder for the duration of `t/run-tests`. Since the 16 pre-existing tests call the var (not a captured reference), they transparently run against the folder-backed factory — late-nil-rejection, weak-lifetime, budget, and sorted-map mutation-miss tests all genuinely exercise the new path, not a stale copy.

**One real nuance, not a bug:** `(assert (nil? (constructor)))` at the top of `-main`, and the `no-injection-retains-the-stock-optional-decline` test, expect the *no-folder* default to decline to `nil` on this gate's host. That's consistent only if this harness's underlying Jolt runtime lacks a global `pmap-fold-seq-order` (the exact gap this feature works around) — in which case only the folder path, not the stock default, can succeed here. The gate therefore demonstrates the folder path's independent correctness but does not simultaneously cross-validate both paths on one host.
