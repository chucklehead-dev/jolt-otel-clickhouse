## Review: opt-in experimental span payload-cache (chdb.clj)

**Scope checked:** `src/otel/exporter/chdb.clj` (`load-experimental-span-codec!` 1275-1310, `execute-closed-compact-rows!` 1319-1364, `insert-direct-span-batch!`/`insert-direct-typed-span-batch!` 1391-1446, exporter validation 1858-1920, `payload-attrs-converter` 143-152), the test file, CHANGELOG, and the SDK entry points in `any_value.clj`/`any_value_native.clj`.

**No correctness defects found.** The feature is internally consistent and the tested invariants hold against the actual code paths:

- **Optionality / gating.** `exporter` (chdb.clj:1877-1880) requires `experimental-span-payload-cache?` to be a strict `boolean?` and, if `true`, requires `experimental-span-codec?` also `true`; this correctly rejects the three cases the test exercises — cache alone (no codec), a non-boolean truthy string, and `nil` (chdb_stock_payload_cache_test.clj:98-112). `load-experimental-span-codec!` (1275-1310) resolves `otel.any-value/scalar-string-map-payload-converter` only when `payload-cache?` is true, and wraps any failure (missing Var, non-`ifn?` factory) into `::experimental-span-payload-cache-unavailable` — all before `jdbc/connection` is ever called at 1956, matching the "fail before storage" requirement and the `(zero? @opens)` assertion in the test.

- **Fresh lexical converter per payload.** `execute-closed-compact-rows!` (1337-1341) calls `(:payload-cache-factory codec)` exactly once per invocation, producing a brand-new cache closure for that call's `rows`. This holds even on later failure: in the encoder-failure test, each attempt (failed and retried) increments the shared `factories` counter once (chdb_stock_payload_cache_test.clj:35-58), confirming no stale/failed cache instance is reused.

- **Propagation to span/resource/event/link.** `cached-projector` for spans (1405-1407, 1444-1446) builds `(fn [span] (span-row span nil true (:nested codec) convert))`, and `span-row`'s `attribute-converter` argument is threaded into `resource-attrs`, `span-attrs`, and into `event-columns`/`link-columns` (277-314, 210-258) — so the same payload-scoped `convert` instance is reused across resource, span, event, and link attribute maps within one batch, which is what makes caching repeated maps profitable and is what the "nested-payloads-do-not-share-cache-state" test actually observes (sequence `[2 1 1]`, two distinct factory ids across the outer and reentrant call).

- **Reentrant/nested exports.** Because `convert` is constructed fresh inside each call to `execute-closed-compact-rows!`, a reentrant call triggered from within a projector (test at chdb_stock_payload_cache_test.clj:60-79) gets its own independent cache and its own `checked-snapshot!`/`compact-format/require-order!` pair (1325-1326, 1360-1363), so outer and inner payloads never share cache or plan state, and each performs its own Durable write.

- **Definition-owned root guard, before and after.** `payload-attrs-converter` (143-152) checks `(identical? key-string original-attribute-key-string)` and the same for `value-string` both before invoking `convert` and after it returns, falling back to `attrs` whenever either check fails. Because `or` in Clojure treats `nil` from either branch as falsy, this composes correctly with the SDK cache's own internal `current?` check (trusted/out of scope here): any decline for any reason — pre-call policy change, post-call policy change, or an unsupported map shape — safely degrades to the live `attrs` path rather than returning stale or policy-inconsistent data. This is exercised precisely by `live-entry-policy-is-checked-before-and-after-cache-conversion` (chdb_stock_payload_cache_test.clj:81-96), and the production code at 143-152 matches that test's expectations.

- **Disabled-path compatibility.** When `(:payload-cache-factory codec)` is nil (cache off), `convert` is nil and the inner `let` in `execute-closed-compact-rows!` (1342) resolves `project` to the *original* `project` argument passed in by the caller — i.e., the pre-existing `(fn [span] (span-row span nil true (:nested codec)))` path, unchanged. (Note: this relies on Clojure's sequential `let` binding semantics, where the right-hand `project` in `project (if convert ... project)` refers to the enclosing function argument, not to itself — correct, but worth a comment if this file is touched again, since it reads like a self-reference at a glance.)

**Minor, non-blocking observation:** the guard in `payload-attrs-converter` only checks chdb's own `key-string`/`value-string` identity, not the SDK's eight-anchor set — that's appropriate layering (the SDK cache already checks its own anchors internally), but the two guard layers aren't visually distinguished in the code, which could read as redundant to a future maintainer unless the SDK's trust boundary is documented nearby.
