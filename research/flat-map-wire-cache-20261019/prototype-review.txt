No concrete correctness defects found. Scope reviewed: `incubator/codec/src/jolt/codec/json.ss` (`ffc-json-encode`, the flat-map cache in `map!`/`fragment!`/`tracked-map-entry!`, and the `ensure-space!`/`byte!` chunking), `incubator/codec/src/jolt/codec/experimental.clj` (`open-codec` option validation, `cached-project` wiring), `incubator/codec/src/jolt/traversal/{experimental.clj,kernel.ss}` (fold contracts the cache relies on), `incubator/codec/test/jolt/codec/{flat_map_cache_test.clj,experimental_test.clj}`, `incubator/codec/README.md`, and `.github/workflows/experimental-codec-stock.yml`.

What was checked against the implementation, with no deviation found:

- **Bounds**: `track?` gates on `map-insertions < 64` and `map-retained < 131072` (json.ss:162); the post-fold guard additionally requires `charge <= 4096` and `map-retained + charge <= 131072` (json.ss:172) before any `hashtable-set!`. All three use `<=`/`<`, matching the stated "at most" semantics, and are checked before the mutating insert, not after.
- **Weak immutable roots**: cache key is `(pmap-root m)` in a `make-weak-eq-hashtable` (json.ss:158, 175), scoped to one lexical `ffc-json-encode` call — `map-cache` is a fresh local per invocation, so there is no cross-call or global persistence.
- **No raw JSON / no output alias**: cached values are freshly allocated bytevector copies (`bytevector-copy!` into a new `bytes`, json.ss:173-174), never the live `tail` buffer; `fragment!` only reads from the cache, never writes back into it.
- **Eligibility piggybacked on the original walk**: `tracked-map-entry!` (json.ss:138-141) observes key/value types during the same `ffc-map-fold` pass that emits bytes; no second traversal is performed, and disqualification (`map-flat? #f`) only suppresses the later cache insert, not the fold itself.
- **Sequence order**: cached bytes are the verbatim output of that one real fold, so a hit replays the original key/value emission order, including hash-collision bucket order from `ffc-pmap-fold` (kernel.ss:22-29).
- **Hit-path depth check**: `fragment!`'s `(fx>=? depth max-depth)` (json.ss:145) is the same bound as the miss-path requirement that entries emit at `depth+1 <= max-depth`; confirmed against `cached-map-does-not-bypass-current-depth-limit` (wrap 127 matches on/off, wrap 128 rejects both, including rejecting a shallow-warmed root hit at the boundary).
- **Hit-path budget check**: `fragment!`'s pre-check `(fx>? n (fx- budget (fx+ completed used)))` (json.ss:147-148) mirrors `ensure-space!`'s lazy budget error; confirmed against the exact-size/`dec`-boundary table in `exact-budget-prefix-and-chunk-boundaries-on-hits`.
- **Chunk-crossing decline**: guarded by `(eq? start-tail tail)` (json.ss:170), which is always false after any `ensure-space!` reallocation (each reallocation always allocates a genuinely new bytevector object), so a map whose encoding spanned a chunk boundary is never cached.
- **Nested state restoration**: `container-depth` and `map-flat?` are restored via `previous`/`previous-flat` (json.ss:160, 179-180) on every path — cached, tracked-and-stored, or disqualified. Insertion/byte counters are intentionally *not* restored on backtrack, since the 64/128KiB budgets are cumulative over the whole invocation rather than per-map, matching the stated contract.
- **Exceptions stop producers**: the cache doesn't touch `ffc-records-fold`'s existing lazy-consumption/stop-on-throw contract (kernel.ss:63-68, "no next record after a callback throws"). Reentrant nested `encode-prefixed-records` calls get entirely fresh lexical state (the `let*` locals inside `ffc-json-encode`, including `map-cache`), so a project callback that re-invokes the codec cannot alias or corrupt the outer call's buffers or cache — consistent with `failure-stops-producer-and-nested-calls-have-independent-storage`.
- **Strict optional constructor options, default off**: `open-codec` rejects any options value other than `{}` or `{:flat-map-cache? <boolean>}`, including a present key with an explicit `nil` or non-boolean value (experimental.clj:44-46); omission defaults to `false` via `(get options :flat-map-cache? false)`. Matches `invalid-options-reject`.
- **Scalar/nested stay uncached**: only the `(pmap? m)` branch in `emit!` (json.ss:194-195) is affected; `write-nested`/`prepare-nested-text` and sorted-map/stock-sorted-map encoding are untouched by the cache, and `candidate?` explicitly excludes sorted maps (`(pmap? m)` only).
- **Persistence ordering**: no change to byte assembly order (`parts`/`tail` reversal at json.ss:211-220) between cached and uncached paths — a hit just substitutes a verbatim byte span into the same position a full walk would have occupied.
- **Documentation/CI consistency**: README's stated bounds (64 insertions, 128KiB, 4KiB) and semantics ("belongs to each `encode-prefixed-records` invocation, not the codec object"; "hits still enforce current output/depth limits") match the code exactly. CI's `(assert (= 14 (:test r)))` matches the actual deftest count (6 in `flat_map_cache_test.clj` + 8 in `experimental_test.clj`).

Every invariant in the brief was traced through both the Scheme implementation and the Clojure bridge/tests; no bound uses the wrong comparison or is checked after the mutating effect, no check is skipped on the hit path relative to the miss path, and no restoration/ordering path diverges from the uncached path. No correctness defect to report.
