# Review: traversal extraction (`jolt.traversal.experimental`)

**No blocking defects found.** The extraction preserves the five properties asked about; two low-severity observations follow, not bugs.

**1. Fold order.** `kernel.ss:5-30` (`ffc-pmap-fold`) walks array-mode roots by increasing index (`:9-13`) and HAMT nodes depth-first in array order (`:14-30`), reversing only hash-collision buckets (`:24-29`, via the `backward` helper) to match stock seq order — confirmed by `experimental_test.clj:8-18`'s colliding-key fixture (`"Aa"`/`"BB"`, same hash, line 14). Sorted-map fold (`kernel.ss:46-50`) is a standard in-order walk, verified against `sorted-map-by` with a comparator-call counter (`experimental_test.clj:33-41`) to confirm no comparator invocation. Vector/records folds (`kernel.ss:53-68`) are index/seq order with no reordering. Order claims check out.

**2. Exception/realization behavior.** Recursive Scheme calls let exceptions unwind naturally — no catch/suppress anywhere in `kernel.ss`. `ffc-records-fold` (`kernel.ss:63-68`) only calls `seq-more` after `visit` returns, so a thrown callback stops the lazy source from realizing further; `experimental_test.clj:43-56` proves this with a `lazy-seq` that records realization (`:next` never appears in `@seen`). `fold-records`/`fold-map` propagate the thrown `Throwable` identity-equal to the caller (`:46-54`). Matches `experimental.clj:59-63` and `kernel.ss:1-4` docstrings.

**3. Immutable-input ownership.** This is a caller contract, not a runtime-enforced guarantee — `experimental.clj:49,55,82` and `kernel.ss:1-4` state inputs must stay immutable for the call's duration; nothing in `kernel.ss` mutates the input collections (`pvec-nth!`'s `!` suffix reads as an internal/unchecked-access naming convention, not mutation of caller-visible state, consistent with `fold-vector`'s "without a seq cursor" claim at `experimental.clj:53-55`). No code-level violation found; this guarantee is inherently unverifiable from source alone against a hostile caller, which the docs already concede.

**4. Map/vector layout fencing.** `experimental.clj:16-30` builds a `qualify` closure checking `record-type-uid`/`record-type-field-names` for pmap, pvec, htable (sorted-map), hcoll, and hnode shapes before `open-traversal` produces a working backend; `kernel.ss:35-39` additionally fences stock sorted-maps by checking the live `clojure.core/sm-ops` cell against the map's own ops. This second check is exercised directly: `experimental_test.clj:40-41` redefs `sm-ops` to `{}` and confirms `fold-map` then rejects. Unsupported reps reject via explicit `error` calls (`kernel.ss:43,51,54`), and Clojure-level wrappers add their own type gates (`experimental.clj:65-66` for records). Fencing is real, not just documented — also verified for empty vectors specifically: `experimental_test.clj:22-24` exercises `n=0` through the native path, so `(pvec? [])` does qualify and the separately-hardcoded `"[]"` literal in `jolt.codec.experimental.clj:56,65` is a documented fixed-spelling shortcut (README.md:53), not a correctness patch over a layout gap — nested empty vectors inside maps/vectors still correctly route through `emit!`'s `pvec?` branch (`json.ss:155-161`) and produce identical output.

**5. Codec lexical native composition, no globals.** `jolt/codec/experimental.clj:24-29` wraps `json.ss` in a `(lambda (ffc-map-fold ffc-vector-fold ffc-records-fold ffc-stock-sorted-map?) ...)` whose parameter names shadow the free identifiers `json.ss` references (`json.ss:148,152,159,165`), so the four native fns captured once via `traversal/native-kernels` (`:29`, sourced from `jolt/traversal/experimental.clj:69-76`) are injected lexically with no top-level `define`. `experimental_test.clj:71` confirms the traversal module itself installs no global (`top-level-bound? 'ffc-map-fold` is false after load), and the test's `-main` (`:73-79`) asserts `jolt.codec.experimental` is never loaded by the traversal-only test run, matching the README and CI's separate gates (`experimental-codec-stock.yml:45-46` vs `:47-51`).

**Minor, non-blocking:**
- `kernel.ss:5-30`'s `walk` assumes a two-tier HAMT shape (array-mode root vs. `hnode`/`hcoll` children); a future node variant not matched by the `cond` (`:20-29`) would silently fall to the `else` pair-cons branch rather than erroring. Already covered by the file's own "version-sensitive, trusted" framing (`:1-4`) — a defensive `error` arm would be cheap insurance if upstream ever adds a third node shape, but is out of scope here.
- README's `## Checks` section (`README.md:107-117`) embeds machine-local absolute paths (`/home/chuck/...`), harmless for this review but not portable for other contributors running the same repro command.
